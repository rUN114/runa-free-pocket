# 周免口袋 0.3.0

Android 上的 Epic 电脑游戏、安卓游戏和 Fab 限时免费内容工具。本次针对用户真机截图中的图片失败、手机游戏误报未拥有进行修改，并加入即将限免。

**已完成构建、逻辑测试、原生代码测试和浏览器界面验证；尚未在安卓真机上验证本版真实账号的手机游戏拥有状态与实际领取。** 预览截图使用官方活动和图片，账号与拥有状态为明确标出的测试样例。

## 安装与使用

1. 安装 `周免口袋-0.3.0-测试版.apk`，可覆盖 0.1.0 / 0.2.0，包名和签名一致。旧版安装包保留。
2. 打开后自动读取电脑活动，已有 Epic 库存授权时自动同步。此次升级会重读活动缓存，保留官方登录 Cookie、账号地区和已有加密授权。
3. 进入手机游戏分类，点击“刷新活动”或“同步库存”，重新核实安卓版本。读取失败会显示失败原因，不根据电脑版本或凭证缺项推断手机版未拥有。
4. Fab 在“账号与同步”中单独连接，读取当前账号的已获取素材库。已有有效 Cookie 时可能直接完成连接。
5. 点击卡片查看简介与预览图。图片加载失败可在详情中点“重试图片”。已下载的图片保存在手机应用缓存中。
6. “即将推出”显示官方已公布的预告、开始时间和独立拥有状态。未开始时不能勾选或领取；开始后刷新活动。官方尚未公布的手机或 Fab 预告不会编造展示。
7. 可隐藏已拥有，选择本期内容后领取。下单前重新同步并跳过已拥有，仅提交明确合计为零的订单。验证码、年龄确认、许可协议需要用户在官方页面处理，领取后重新核实。

最低 Android 8.0，需要支持安全网页消息和页面启动脚本的 Android System WebView。活动、授权和领取需要联网，程序在前台运行。网络无法访问官方图片服务器时仍可能加载失败，本机缓存不能替代首次联网。

## 本版修改

- 图片改为安卓原生 HTTPS 下载，再通过本机地址显示。仅处理列表中登记的官方图片；验证格式头与大小，使用磁盘缓存，缩略图失败时重试同一张原图。详情封面和图库提供重试，不再保留破损图片图标。
- 不再将“直接凭证没有该 ID”判定为未拥有。先读取完整有效凭证，再为未匹配的准确商品查询 Epic 商品权限，覆盖通过其他商品继承的权限。电脑与安卓继续按各自的命名空间和 catalog-item ID 判断。
- 权限查询只接受直接从 Epic HTTPS 返回、账号与有效期匹配的响应；协议异常、401/403、缺失字段或非布尔拥有状态均作为失败。响应令牌不接受网页或其他客户端传入，也不对外转发。
- 仅直接请求的商品权限证明可给出未拥有结论；缓存缺项、请求失败和未知商品 ID 仍然是未能确认或同步失败。
- 电脑解析当前活动和官方预告；安卓从官方 freeGame 报价中读取当前或未来的免费 Claim，优先当前有效报价。活动阶段与拥有状态分开，因此预告也能显示已拥有。
- 界面选择、原生队列、网页下单前分别检查活动是否开始及结束；预告无法通过直接传入勾选键绕过。
- 库存同步只更新当前分类，避免同步电脑时覆盖安卓结果。旧活动缓存重新读取，不沿用上一版的错误负面状态。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| 已拥有 | 当前账号有效凭证、准确商品权限、官方商品页或 Fab 已获取素材库已确认 |
| 已拥有 · 缓存 | 上次确认拥有，本次尚未完成同步，卡片显示上次时间 |
| 未拥有 | 准确商品权限或完整 Fab 素材库确认未拥有 |
| 部分已拥有 | 组合商品只拥有部分内容，其余部分已完成权限核实 |
| 未能确认 | 未连接、未同步或缺少准确的商品资料 |
| 同步失败 | 请求、授权或解析失败，不能据此认定未拥有 |
| 即将限免 | 独立的活动阶段；仍可同时显示已拥有或未拥有，开始前不可领取 |

## 代码与构建

- `MainActivity.java`：安卓界面、来源校验、任务队列、分类同步、原生领取拦截及本机图片响应。
- `EpicSession.java / EpicEntitlements.java`：Keystore 加密授权、凭证分页和准确商品权限查询。
- `OfficialImages.java`：受限图片下载、格式头检查、原图重试和磁盘缓存。
- `assets/domain.js`：活动阶段、媒体资料、拥有状态和选择规则。
- `assets/automation.js`：官方网页登录、Fab 素材库和零元网页领取。
- `assets/ui.js / style.css / index.html`：手机卡片、预告区、详情图库和图片重试。
- `app/src/test`：原生权限和图片测试；`tests`：JavaScript 与原生分页测试。

JDK 17+、Android SDK Platform 35、Build Tools 36；附 Gradle 9.3.0 Wrapper。生产依赖仍只有原有 AndroidX WebKit 及传递依赖。新增 JUnit 4.13.2 和 org.json 20240303 **仅用于测试**；Android SDK 的 JSON 在本地 JVM 中是桩实现，不能用于验证实际解析行为。它们不会打入 APK。

```powershell
# 工程目录执行；local.properties 中配置自己的 SDK，例如 sdk.dir=D\:/Android/sdk
./gradlew.bat assembleDebug lintDebug testDebugUnitTest
./tests/run-tests.ps1
```

Epic 商品权限查询依据 [Epic 官方拥有状态说明](https://dev.epicgames.com/docs/web-api-ref/ownership-verification-using-rest?lang=ja)，兼容客户端请求参考 [egs-api-rs](https://github.com/AchetaGames/egs-api-rs)。登录方式与库存权限仍取决于服务端，拒绝访问时会报错。

小黑盒用于理解界面和流程。新提供的 APK 静态身份为 `com.imbastar.c5game` / C5Game 4.9.0，不能当作 Epic 官方安卓客户端；限定资源检查未发现可直接依据的 Epic 库存实现。本工程没有复制这些应用的品牌、业务脚本、私有后台或账号体系，未向它们发送用户账号。
