# 1.0.1 审核意见修复计划

用户已授权按核实后的审核意见修复。目标是修复可复现问题，保留同步保存、零元限制、账号绑定和中断后先核实的规则，不做整个 Activity 的重构。

1. Wrapper 保留用户已升级的 9.8.2，补官方发行包 SHA256、超时和 URL 验证；README 同步版本。Qodana 使用 Android 镜像，仓库内容权限降为只读，保留评论/标注功能所需权限。核对 YAML 和官方校验和，不触发外部发布。
2. UI 数字价格转换为显示字符串；扩展已有浏览器测试，覆盖数字价格及 receiveState 清除已拥有、过期、已移除选择。把浏览器测试入口明确纳入检查脚本，依赖缺失时显式报错。
3. 金额识别保留三态语义，增加缺失/多条/无法解析的原因；排除与当前商品名完全相同的标题行，避免 Total War 被误当合计。不以宽松关键词代替零元证据。增加中文免费卡片和 Fab 结算许可检查；控件缺失时仅接受明确且唯一的许可摘要，否则暂停。
4. 提取可单测的商店消息来源规则，保留官方结算子帧并阻止跨商店、错误主帧及错误任务类型消息。畸形消息只记录不含凭据的日志，不写失败账本；恢复任务的正常业务拒绝单独向用户显示原因。同步 checkpoint 不改。
5. 调查正式版设备测试脚本 Kotlin 运行类缺失，优先修测试构建而不增大发行包；若无法在本次合理范围解决，保留实证和限制，不宣称正式版设备验收成功。
6. 运行 JVM、Node、浏览器和安卓构建/静态检查。使用独立审核代理复核完整 diff，修复有效意见后重跑受影响检查，再做本地 Git 提交。用户其他 Kotlin、IDE 配置不纳入提交。

验证只使用样例数据及隔离模拟器，不提交真实订单。Fab accountId 是账号绑定元数据而非会话凭据，文档需说明与 WebView Cookie、KeyStore 令牌的区别，避免把账号标识当作授权凭证。

完成记录：52项JVM、87项JS、四宽度浏览器、正式构建、Lint和非调试构建模拟器故障注入均通过；独立审核意见已补回归并复核。没有真实订单和云扫描验证。
