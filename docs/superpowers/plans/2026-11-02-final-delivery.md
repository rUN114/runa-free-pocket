# 1.1.0 交付计划

**目标：** 补完 GLM 的归档和云端验证交接，交付可覆盖更新的小体积签名 APK；页面和真实订单由用户验收。

**边界：** 唯一开发入口为 `D:/Android/Projects/runa-pocket-native`。不打开应用，不修改账号、Cookie 或领取记录，不删除旧源码，不合并安卓应用代码到 main，不创建 GitHub Release。沿用既有包名、正式签名、许可持久化和待核实订单保护。

- [x] 校验已有四份归档的 SHA256、ZIP 内容及 bundle 完整性；补正常文件名 ZIP，在隔离目录恢复并逐文件比较；原归档和原目录保留。
- [x] `.github/workflows/tests.yml` 加入探针及设备摘要的离线 Python 测试，明确 contents: read；每周在线探针继续由默认分支的独立工作流负责，避免未来合并后重复定时任务。
- [x] `app/build.gradle` 定为 1.1.0 / versionCode 13。只清理本轮发现的过时注释及无效 Lint 抑制，不改领取逻辑。
- [x] 重跑 JS、Python、JVM、Lint，编译诊断测试包和正式签名 APK；核验包名、版本、非调试、证书、体积及 SHA256。不把这些检查写成页面或真实下单验收。
- [x] 由独立上下文审核本轮 diff、调用方与验证记录；审核未发现需修复的代码或CI缺陷，要求最后核实交付目录、标签及当前提交云端结果。
- [x] 更新 README、CHANGELOG 及交付记录，检查完整 diff；APK及校验文件已复制到桌面和D盘交付目录，原APK保留。

## 提交后验收

待提交内容扫描通过后，仅提交并推送开发分支；确认该源码提交的云端检查通过，再为实际交付源码建立本地`v1.1.0`标签。最终提交、Actions链接和交付文件校验结果写入仓库外的交付目录，不通过预先勾选代替这些实际动作。默认分支探针沿用已完成的独立运行，不合并安卓代码或创建GitHub Release。
